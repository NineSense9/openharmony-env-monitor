## 目的

用户反馈烧录后 LCD 和 K3-K6 表现“没有变化”。先核对构建链路和烧录目录，确认
是否真的使用了最新的 ADC5 诊断固件，再继续判断板级输入。

最终镜像中检索到 `ADC5 USER KEY`、`KEY_UNKNOWN` 和 ADC5 诊断字符串；最终构建库为
`liblab02_key_lcd_adc_diagnostic.a`，没有链接旧的 `liblab02_key_lcd` 或
`liblab01_lcd`。

构建输出保留了 SDK LCD 源码已有的 `missing braces`、`LOS_Msleep` 隐式声明和
`strlen` signedness 警告；这些是已有基线警告，本次未改变 LCD 驱动逻辑，未导致构建
失败。

## 同步边界问题

服务器新产物时间为 2026-09-01 01:28，而 Windows 烧录目录原文件时间为
2026-08-31 23:44。原目录因此仍是旧诊断包，用户烧录后看到旧画面属于预期结果，不能
据此判断 ADC5 诊断代码无效。

服务器端 `md5sum` 与 Windows 端 `Get-FileHash -Algorithm MD5` 结果一致。

## 当前结论

代码和构建链路已确认到 ADC5 诊断版本，之前的“无变化”反馈不能用于判断板子输入，
因为实际烧录的是旧包。下一次上板只使用上述目录中的两个文件，并保存完整 UART：
先所有按键松开并复位，观察 2 秒；再依次按住、松开 K3、K4、K5、K6，各保持约 2 秒。
