> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在独立目录中实现 RK2206 `K3-K6` 共用 ADC5 的用户按键识别，保存可复现源码、补丁、测试和构建记录。

**Architecture:** 实验源码使用老师 `b1_adc` 已验证的 `DevIoInit`、`LzSaradcInit` 和 `LzSaradcReadValue(5, ...)` API。程序以 20 ms 周期读取 ADC，使用 3 次连续同档确认稳定状态，输出原始值、电压和档位；`K1=RESET`、`K2=MASKROM` 只记录为硬件边界，不参与用户按键识别。按键电压与 `K3-K6` 标签顺序先保留为板上标定结果，不凭猜测写死。

**Tech Stack:** C、OpenHarmony LiteOS-M、RK2206 SAR ADC、GN、Makefile、Python `pytest`、UART 115200 8N1。

- [ ] **Step 1: Implement the minimal board-specific reader**

Use the following behavior:

```c
#define ADC_CHANNEL 5
#define SAMPLE_INTERVAL_MS 20
#define DEBOUNCE_SAMPLES 3

typedef enum {
    KEY_LEVEL_RELEASED = 0,
    KEY_LEVEL_K3,
    KEY_LEVEL_K4,
    KEY_LEVEL_K5,
    KEY_LEVEL_K6,
    KEY_LEVEL_UNKNOWN,
} KeyLevel;
```

Initialize `GPIO0_PC5` with a `DevIo` structure matching the `b1_adc`
example, call `DevIoInit`, `LzSaradcInit`, and read with
`LzSaradcReadValue(ADC_CHANNEL, &data)`. Convert with
`(float)(data * 3.3 / 1024.0)`.

Classify the release state above the fourth known band and classify the four
known voltage bands using explicit raw ADC windows around the documented
nominal values. Keep the label mapping in a named table so it can be updated
after the first board sampling. For an out-of-band value, return
`KEY_LEVEL_UNKNOWN`.

The task prints one startup line and one line per stable state change containing
`raw`, `voltage`, and the symbolic level. It must not call
`IoTGpioGetInputVal()` or claim that K1 is a user input.
